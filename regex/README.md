# Gitleaks → StringGroup JSON Database

Machine-readable conversion of [`scripts/gitleaks.toml`](scripts/gitleaks.toml)
(222 rules) into a JSON asset layout that **mirrors** the
[`stringgroup/`](../stringgroup/README.md) folder structure — while keeping the
two databases fully separate (this tree is generated from gitleaks only and
never touches the curated `stringgroup/` database).

---

## Layout

```
regex/
├── scripts/
│   ├── gitleaks.toml                  # source of truth (auto-generated by gitleaks)
│   ├── verify-gitleaks.py             # small cross-check of the TOML structure
│   └── gitleaks-to-stringgroup.py     # parser: TOML -> assets/ (this is the builder)
│
└── assets/                            # generated runtime layout (222 groups)
    ├── gitleaks-rules.json            # COMPREHENSIVE DB — every rule, every field
    ├── stringgroups.json              # Group -> Keywords  (keyed by rule id)
    ├── keyword-index.json             # Keyword -> Group   (flat O(1) lookup map)
    └── groups/                        # one file per rule
        ├── 1password-secret-key.json
        ├── aws-access-token.json
        ├── generic-api-key.json
        └── ... (222 files)
```

Everything under `assets/` is **generated** — regenerate it, never hand-edit it.

---

## File formats

### 1. `assets/gitleaks-rules.json` — the comprehensive database

Preserves **every** field of the TOML, losslessly:

```json
{
  "title": "gitleaks config",
  "minVersion": "v8.25.0",
  "allowlist": {
    "description": "global allow lists",
    "paths": ["..."],
    "regexes": ["..."],
    "stopwords": ["..."]
  },
  "rules": [
    {
      "id": "generic-api-key",
      "description": "...",
      "regex": "...",
      "entropy": 3.0,
      "keywords": ["access", "api", "key", "..."],
      "allowlists": [
        { "regexTarget": "match", "regexes": ["..."], "stopwords": ["..."] },
        { "condition": "AND", "paths": ["..."], "regexTarget": "line", "regexes": ["..."] }
      ]
    }
  ]
}
```

Rule-level fields covered: `id`, `description`, `regex`, `entropy`, `keywords`,
`path` (path-only rules such as `pkcs12-file`), `secretGroup`, and per-rule
`allowlists` — each allowlist keeps its own `description`, `paths[]`,
`regexes[]`, `regexTarget` (`"match"`/`"line"`), `stopwords[]`, and `condition`
(`"AND"`) verbatim.

### 2. `assets/stringgroups.json` — Group → Keywords

Object keyed by gitleaks rule **id** (one group per rule):

```json
{
  "aws-access-token": ["a3t", "akia", "asia", "abia", "acca"],
  "github-pat": ["ghp_"],
  "openai-api-key": ["t3blbkfj"]
}
```

### 3. `assets/keyword-index.json` — Keyword → Group

```json
{ "ghp_": "github-pat", "xoxb": "slack-bot-token", "...": "..." }
```

Detection is a single hash lookup, exactly like the stringgroup runtime index.

### 4. `assets/groups/<rule-id>.json` — one file per rule

```json
{ "name": "aws-access-token", "keywords": ["a3t", "akia", "asia", "abia", "acca"] }
```

Same strict `{name, keywords}` shape as `stringgroup/assets/groups/*.json`.

## Conversion policy

- **One rule = one group**, named by the rule `id` — the two databases are kept
  as separate concepts.
- **Keywords** are the rule's raw gitleaks `keywords`, verbatim. They are
  pre-filter substrings (`sk-`, `ghp_`, `AKIA`-prefix tokens, ...), so no
  casing-variant expansion is applied (unlike the curated stringgroup build).
- **Collisions** — 37 keywords are declared by more than one rule
  (e.g. `twitter` ×5, `cloudflare` ×3). The index keeps **first-occurrence
  wins** (matching `stringgroup/scripts/stringgroups/emit-assets.mjs`), and
  every remap is printed on build so nothing is silently lost.
- **Keyword-less rules** (`pkcs12-file`, a path-only rule) get keywords derived
  from their id so they still appear in the index.
- **Deterministic** — same TOML in, identical assets out.

## Build & validate

Requires **Python ≥ 3.11** (`tomllib` is stdlib). No third-party packages.

```bash
# 1. structural cross-check of the TOML (the small verification script)
python regex/scripts/verify-gitleaks.py

# 2. regenerate regex/assets/ from scripts/gitleaks.toml
#    (prints cross-verification, generation summary and a self-check;
#     self-check exits non-zero on any inconsistency)
python regex/scripts/gitleaks-to-stringgroup.py

# optional: check-only mode (no file writes)
python regex/scripts/gitleaks-to-stringgroup.py --verify
```

The builder's self-check verifies:

- every index keyword maps to a group that actually contains it
- every group keyword is either in the index or listed as a collision
- every collision's index owner is one of its claimants
- one per-group file per rule, matching `stringgroups.json` 1:1
